## 워크플로우 조건분기(IF) 조건식 작성 가이드

워크플로우 빌더의 조건분기 노드는 `if` / `else if` / `else` 로 흐름을 나눈다.
이 문서는 각 조건에 넣는 **조건식**을 어떻게 쓰는지 설명한다.

### 흐름 규칙

1) 조건은 상세창에 나열된 순서(`if`, `else if` ...)대로 위에서부터 판정한다.
2) 처음 참이 된 조건의 가지로만 흐른다. 아래 조건들은 평가하지 않는다.
3) 모든 조건이 거짓이면 `else` 가지로 흐른다.
4) 선택되지 않은 가지의 노드는 실행되지 않고 응답에도 담기지 않는다.
5) 가지마다 다른 노드로 이어지지만, **여러 가지를 같은 노드로 다시 모을 수 있다.**
   `if -> A -> C`, `else -> B -> C` 처럼 C 는 하나만 만들어 양쪽에서 이어두면 된다.
   합류 노드는 어느 가지로 흘러왔든 한 번만 실행된다.
6) 조건분기 노드는 내보내는 메시지가 없으므로 응답메시지ID(OUT)를 쓰지 않는다.
   대신 **요청메시지ID(IN)는 반드시 채운다.** 조건식이 볼 수 있는 것은 그 슬롯 하나뿐이다.

### 가지 연결하기

노드는 캔버스 위에 자유롭게 놓고, 흐름은 카드 아래의 **출력포트**를 끌어서 잇는다.
노드 위치는 카드 **왼쪽 손잡이**를 끌어 옮기고, 카드 본문을 누르면 상세창이 열린다.

- 조건분기 노드에는 조건 개수만큼의 포트(`if`, `else if` ...)와 `else` 포트가 달린다.
- 포트를 끌어 다른 노드에 놓으면 그 가지가 그 노드로 이어진다. 이미 이어진 포트를 다시 끌면 연결이 옮겨간다.
- 빈 포트를 그냥 누르거나 빈 곳에 놓으면 새 노드를 만들어 바로 이어준다.
- 연결선 위에 마우스를 올리면 나오는 `×` 로 연결만 끊을 수 있다.
- 한 포트에서 나가는 길은 하나지만, 한 노드로 들어오는 길은 몇 개든 된다. 합류는 이 규칙 덕분에 가능하다.
- 들어오는 연결이 없는 노드가 시작 노드(`시작` 배지)다. 흐름에 닿지 않는 노드는 `미연결` 배지로 표시되고 실행되지 않는다.

### 조건식은 자바스크립트다

- 한 줄로 쓰면 그대로 결과값이 판정에 쓰인다. 내부적으로 `return (조건식)` 으로 감싸서 실행한다.
- 식 안에 `return` 이 들어있으면 여러 줄 스크립트로 보고 그대로 실행한다.
- GraalVM 스크립트 엔진에서 외부 접근이 차단된 채로 실행된다. 자바 클래스나 파일, 네트워크는 쓸 수 없다.

```js
// 한 줄
params.length > 0 && params[0].status === 'OK'
```

```js
// 여러 줄
var row = params[0];
if (!row) return false;
return row.eval_way_cd === 'QUANT_EVAL' && Number(row.score) >= 60;
```

### 조건식에서 쓸 수 있는 값

조건식이 참조할 수 있는 것은 `params` 하나다. 이 노드의 요청메시지ID(IN) 슬롯이다.
서버에서 한 슬롯은 `List<Map<String,Object>>` 이고, 이것이 JSON을 거쳐 조건식에서는
**객체(행)들의 배열**로 들어온다. 행 하나가 조회 결과 한 줄이고, 컬럼이 그 행의 속성이다.

```js
params           // [ { eval_way_cd: 'QUANT_EVAL', score: 80 }, { ... } ]
params.length    // 행 수
params[0]        // 첫 행 (없으면 undefined)
params[0].score  // 첫 행의 score 컬럼
```

다른 노드의 결과로 판단하고 싶으면 조건분기 노드의 **요청메시지ID를 그 슬롯으로 바꿔서** 받는다.

### 자주 쓰는 패턴

```js
// 조회 결과가 한 건이라도 있으면
params.length > 0

// 첫 행의 값 비교 (가장 많이 쓰는 형태)
params.length > 0 && params[0].status === 'OK'

// 여러 값 중 하나
params.length > 0 && ['A', 'B'].indexOf(params[0].grade) >= 0

// 한 건이라도 조건에 걸리면
params.some(function(row) { return row.status === 'NG'; })

// 전부 조건에 맞아야 하면 (빈 배열은 every 가 참이 되므로 건수 확인을 같이 둔다)
params.length > 0 && params.every(function(row) { return row.confirm_yn === 'Y'; })

// 합계로 판단
params.reduce(function(sum, row) { return sum + Number(row.amount || 0); }, 0) > 10000

// 값이 비어있는지
!params[0].reject_reason
```

### 참/거짓 판정 규칙

조건식이 꼭 `true`/`false` 를 돌려줄 필요는 없다. 결과값을 아래 규칙으로 해석한다.

| 결과값 | 판정 |
| --- | --- |
| `true` / `false` | 그대로 |
| 숫자 | 0이면 거짓, 그 외 참 |
| 문자열 | 빈 문자열이면 거짓, 그 외 참 |
| 배열 | 비어있으면 거짓, 그 외 참 |
| 객체 | 참 |
| `null` / `undefined` | 거짓 |
| 빈 조건식 | 거짓 |

주의할 것은 **문자열 `'false'` 나 `'N'` 도 참**이라는 점이다.
플래그 컬럼은 값을 그대로 두지 말고 `row.use_yn === 'Y'` 처럼 비교식으로 쓴다.

### 자주 겪는 문제

**슬롯이 비어있는데 첫 행을 꺼내면 에러가 난다.**
앞 노드가 한 건도 돌려주지 않았거나 요청메시지ID를 비워두면 `params` 는 빈 배열이다.
이때 `params[0].status` 는 스크립트 에러가 되고, 워크플로우 전체가 `E-WORKFLOW-005` 로 멈춘다.
길이 확인을 앞에 두면 에러 없이 거짓으로 흐른다.

```js
params[0].status === 'OK'                        // 슬롯이 비면 실행 실패
params.length > 0 && params[0].status === 'OK'   // 슬롯이 비면 그냥 거짓
```

**컬럼명 대소문자.**
SQL 노드의 결과 키는 JDBC 드라이버가 알려주는 컬럼명을 그대로 쓴다.
MySQL과 MariaDB는 SQL에 쓴 대로, Oracle과 H2는 대문자로 올라온다.
상단 **실행** 버튼으로 워크플로우를 한 번 돌려보고, 응답 JSON에 찍힌 키를 그대로 복사해 쓰는 것이 확실하다.

**없는 컬럼은 조용히 거짓이 된다.**
오타가 나도 에러가 아니라 `undefined` 와의 비교가 되어 거짓으로 흐른다.
의도한 가지로 안 가면 컬럼명부터 확인한다.

**날짜 컬럼.**
드라이버 타입에 따라 문자열로 오기도 하고 숫자(epoch)로 오기도 한다.
날짜 비교가 필요하면 SQL에서 비교하기 좋은 문자열로 포맷해서 내보내거나,
메시지처리(MESSAGE_PROCESSOR) 노드에서 한 번 가공한 뒤 판단하는 편이 안전하다.

**숫자 비교.**
문자 컬럼으로 들어온 숫자는 `Number(row.score) >= 60` 처럼 감싸서 비교한다.

**빈 배열에서의 every.**
자바스크립트는 빈 배열의 `every` 를 참으로 본다. 한 건도 없는데 "전부 만족" 으로 흘러버리므로
`params.length > 0 &&` 을 앞에 붙여 건수를 함께 확인한다. `some` 은 반대로 빈 배열이면 거짓이라 그대로 써도 된다.

### 확인 방법

1) 상단 **실행** 버튼으로 요청 메시지를 채워 워크플로우를 돌린다.
2) 실행 결과 JSON에 어떤 슬롯이 담겼는지 본다. 타지 않은 가지의 응답 슬롯은 아예 없다.
   이것으로 어느 가지로 흘렀는지 알 수 있다.
3) 조건식에 문제가 있으면 응답이 `E-WORKFLOW-005`(조건분기 판정식 실행 실패)로 온다.
4) 노드 연결이 순환하면 `E-WORKFLOW-006`(실행 단계 초과)으로 온다.

### 저장되는 모양 (참고)

| 테이블 | 내용 |
| --- | --- |
| `WORKFLOW_FUNCTION` | 노드. 조건분기 노드는 `FUNCTION_TYPE = CONDITION` |
| `WORKFLOW_CONDITION` | 조건 한 줄(`if`, `else if`). `ORDER_NUM` 이 판정 순서, `BRANCH_ID` 가 가지 식별자 |
| `WORKFLOW_EDGE` | 노드 연결. 조건 가지는 `CASE` + 같은 `BRANCH_ID`, 나머지 가지는 `ELSE` |
